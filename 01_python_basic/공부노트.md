### 4. 변수·자료형·입출력

#### 값마다 자료형이 있다
Python에서는 변수 선언문에 자료형을 따로 적지 않아도 대입된 값을 보고 자료형을 판단한다. 같은 이름에 다른 자료형의 값을 다시 연결할 수도 있지만, 값의 의미가 갑자기 바뀌면 코드를 이해하기 어려워진다.

예제 파일: 01_basics/03_data_types.py
```py
request_count = 7
average_seconds = 1.75
status_message = "완료"
is_healthy = True
last_error = None

# __ = 더블 언더스코어
# __""__ = 매직 메소드
print(type(request_count).__name__) 
print(type(average_seconds))
print(type(status_message).__name__)
print(type(is_healthy).__name__)
print(type(last_error).__name__)
```

#### 문자열은 순서가 있는 문자 모음이다

예제 파일: 01_basics/04_strings.py
```py
raw_status = "  Success  "
#strip() 메서드는 문자열의 양쪽 공백을 제거합니다.
#lower() 메서드는 문자열을 소문자로 변환합니다.
normalized_status = raw_status.strip().lower()
message = "검색 에이전트가 문서 12개를 찾았다."

#!r은 따옴표를 추가해준다.
print(f"원본: {raw_status!r}")
print(f"원본: {raw_status}")
print(f"정리: {normalized_status!r}")
print(f"첫 글자: {message[0]}")
print(f"앞 네 글자: {message[:4]}")
print(f"요약: {message}")
```
```sh
원본: '  Success  '
원본:   Success  
정리: 'success'
첫 글자: 검
앞 네 글자: 검색 에
요약: 검색 에이전트가 문서 12개를 찾았다.
```

#### 출력 형식을 조절하기

여러 값을 print()에 전달하면 기본 구분자는 공백이다. sep은 값 사이의 구분자를, end는 출력 끝의 문자를 바꾼다. 상태와 값 목록을 한 줄 로그로 읽기 좋게 만들 때 유용하다.
```py
agent = "검색"
status = "success"

print("기본 출력:", agent, status)
print("구분자 변경:", agent, status, sep=" | ")
print("상태:", end=" ")
print(status)
```
```sh
기본 출력: 검색 success
구분자 변경: | 검색 | success
상태: success
```

### 5. 컬렉션: list·tuple·dict·set

#### 여러 값을 왜 묶는가
  list: 순서가 있고 변경할 수 있다.
    작업 목록처럼 추가·수정되는 값
  tuple: 순서가 있고 생성 후 변경할 수 없다.
    좌표처럼 하나의 고정된 값 묶음
  dict: 키와 값의 쌍으로 저장한다.
    실행 기록처럼 항목 이름이 필요한 정보
  set: 중복을 허용하지 않고 순서를 기준으로 다루지 않는다.
    고유 태그와 중복 제거

예제 파일: 02_collections/01_list_tuple.py
```py
agents = ["검색", "분석", "요약"]
agents.append("검증")
agents[1] = "분석 및 정리"

coordinates = (37.5, 127.0)

print(agents)
print(agents[0])
print(agents[-1])
print(coordinates)
```
```sh
['검색', '분석 및 정리', '요약', '검증']
검색
검증
```

#### list 변경 메서드와 반환값

예제 파일: 02_collections/02_list_mutation.py

```py
# 시작 목록을 확인한다.
agents = ["검색", "분석"]
print("1) 시작 목록:", agents)

# append()는 마지막에 하나를 추가하고 반환값은 None이다.
append_result = agents.append("요약")
print("2) append 반환값:", append_result)
print("3) append 뒤:", agents)

# extend()는 여러 항목을 더하고, insert()는 원하는 위치에 넣는다.
agents.extend(["검증", "보고"])
agents.insert(1, "분배")
print("4) extend와 insert 뒤:", agents)

# pop()은 항목을 꺼내고, remove()는 지정한 값을 삭제한다.
last_agent = agents.pop()
agents.remove("분석")
print("5) pop으로 꺼낸 항목:", last_agent)
print("6) remove 뒤:", agents)
```
```sh
1) 시작 목록: ['검색', '분석']
2) append 반환값: None
3) append 뒤: ['검색', '분석', '요약']
4) extend와 insert 뒤: ['검색', '분배', '분석', '요약', '검증', '보고']
5) pop으로 꺼낸 항목: 보고
6) remove 뒤: ['검색', '분배', '요약', '검증']
```

#### 안전한 조회와 집합 연산

예제 파일: 02_collections/04_collection_safety.py

```py
# 같은 dict 키에 새 값을 대입하면 기존 값이 덮어써진다.
run = {"agent": "검색", "status": "queued"}
run["status"] = "retrying"
print("1) 갱신한 상태:", run["status"])

# get()은 없는 키를 기본값과 함께 안전하게 조회한다.
print("2) 재시도 횟수:", run.get("retry_count", 0))

# 아래 줄은 없는 키를 대괄호로 조회하므로 KeyError가 발생한다.
# print(run["retry_count"])

# discard()는 set에 값이 없어도 오류가 나지 않는다.
tags = {"python", "ai", "orchestration"}
tags.discard("missing")
print("3) discard 뒤 태그 개수:", len(tags))

# 아래 줄은 없는 값을 삭제하므로 KeyError가 발생한다.
# tags.remove("missing")

# 집합 연산은 공통된 권한과 아직 없는 권한을 비교할 때 쓸 수 있다.
required_permissions = {"read", "summarize", "review"}
granted_permissions = {"read", "summarize"}
print("4) 사용 가능한 권한:", required_permissions & granted_permissions)
print("5) 추가로 필요한 권한:", required_permissions - granted_permissions)
#합집합 #추가됨
print("6) 모든 권한:", required_permissions | granted_permissions)
```
```sh
1) 갱신한 상태: retrying
2) 재시도 횟수: 0
3) discard 뒤 태그 개수: 3
4) 사용 가능한 권한: {'read', 'summarize'}
5) 추가로 필요한 권한: {'review'}
```

#### 가져오기만 했는데 출력이 된다면?

이제 만든 패키지의 delivery.py를 다시 사용한다. 이 파일의 끝에 배송비를 확인하는 print()를 조건 없이 넣으면, 05_package_demo.py가 이 모듈을 가져올 때 확인 문장까지 먼저 출력된다. 가져오기는 함수만 복사하는 동작이 아니라 모듈의 최상위 코드도 처리하기 때문이다.

먼저 확인: shop_tools/delivery.py 끝에 한 줄 추가

```py
print("테스트) 배송비 단독 확인:", calculate_delivery_fee(12000))
```

이 상태에서 05_package_demo.py를 실행하면 기존 주문 결과 앞에 다음 줄이 끼어든다.
```sh
테스트) 배송비 단독 확인: 3000
1) 첫 주문: 연필 세트: 상품 12000원 + 배송 3000원 = 15000원
2) 두 번째 주문: 노트 묶음: 상품 35000원 + 배송 0원 = 35000원
```

주문 파일은 배송비 함수를 가져와 사용할 뿐인데, 배송비 파일의 단독 확인까지 실행된 것이다. 이제 방금 추가한 print() 한 줄을 아래 코드로 교체한다.

최종 코드: shop_tools/delivery.py 끝에 남길 부분

```py
if __name__ == "__main__":
    print("테스트) 배송비 단독 확인:", calculate_delivery_fee(12000))
```

delivery.py를 직접 실행하면 테스트) 배송비 단독 확인: 3000이 나타난다. 05_package_demo.py를 실행하면 앞에서 본 두 주문 결과만 나타나고 단독 확인은 끼어들지 않는다.

파이썬은 실행 중인 파일에 __name__이라는 이름을 정한다. delivery.py를 직접 실행할 때는 "__main__", shop_tools.delivery로 가져올 때는 "shop_tools.delivery"다. 따라서 위 조건은 직접 실행할 때만 참이 된다. __init__.py는 패키지 폴더를 위한 파일이고, 이 __name__ 조건은 현재 파일을 어떻게 사용하는지 확인한다. 이름이 비슷해 보여도 역할은 다르다.

### Codex로 작은 기능 구현·오류 수정·검증하기

#### 요청은 작업 크기에 맞춘다

Codex를 쓸 때 요구사항 양식을 매번 채울 필요는 없다. 먼저 만들거나 고칠 동작과 확인할 결과를 한두 문장으로 말한다.

파일 위치나 사용할 문법이 결과에 영향을 줄 때는 그 조건을 덧붙인다. 실행 결과가 예상과 다르면 **실패 입력·기대 결과·실제 결과**를 후속 요청에 전달한다. 복잡한 작업에서는 목표, 관련 파일, 제약, 완료 조건을 더 분명히 적는다.

비밀키, 비밀번호, 개인정보와 공개할 수 없는 업무 데이터는 Codex에 전달하지 않는다.

#### 코드 생성 실습: 작업 입력 점검하기

작업 목록을 사용하기 전에 이름이 비어 있거나 상태를 잘못 적은 항목을 찾는다.  05_genai_coding_debugging/task_input_lab 폴더를 만들고 연다. 다음 요청을 Codex에 전달한다.

```
task_input_lab 폴더에 main.py와 validation.py를 만들어 줘.
작업은 {"작업 이름": 문자열, "상태": 문자열} 형태의 dict다. 작업 이름은 빈 문자열이면 안 되고, 상태는 "완료", "진행 중", "대기"만 허용한다.
main.py에서 오류 로그 확인(완료), API 응답 확인(진행 중), 작업 이름이 ""인 작업(대기), 배포 대기(멈춤)를 검사해 줘.
validation.py의 find_invalid_tasks(tasks)는 잘못된 항목의 설명을 리스트로 반환하고, main.py는 그 함수를 가져와 결과를 출력하게 해 줘.
리스트·딕셔너리·조건문·반복문·함수·모듈만 사용하고 외부 패키지 없이 실행해 실제 결과와 만든 파일을 알려 줘.
```

#### 실행 결과 확인

`main.py`를 실행한다. 출력 문구는 달라도 세 번째 작업은 이름이 비어 있고, 네 번째 작업의 `멈춤`은 허용되지 않은 상태라고 나와야 한다. 앞의 두 작업은 문제가 없어야 한다.

`validation.py`의 함수가 문제 목록을 `return`하고 `main.py`가 그 함수를 가져와 출력하는지 확인한다. 빈 작업 목록을 넣었을 때 문제 목록이 비는지도 확인한다. 결과가 다르면 해당 입력과 실제 출력을 Codex에 전달해 수정하게 한다.

#### 오류 수정 실습: 잘못된 상태가 정상으로 나오는 문제

task_input_lab 폴더에 debug_status.py를 만들고 아래 코드를 그대로 붙여 넣는다.

```py
"""작업 상태가 허용되는지 확인한다"""

def check_status(status: str) -> str:
    if status == "완료" or "진행 중" or "대기":
        return "정상"
    return "잘못된 상태"


if __name__ == "__main__":
    for status in ["완료", "진행 중", "멈춤"]:
        print(status, check_status(status))
```

실행하면 `완료`, `진행 중`, `멈춤`이 모두 `정상`으로 나온다. 기대 결과는 `멈춤 잘못된 상태`다. 코드는 실행되지만 조건식 때문에 잘못된 결과가 나오는 논리 오류다.

잘못된 출력과 기대 결과를 Codex에 전달한다.

```
`debug_status.py`에서 `멈춤`이 정상으로 나온다. 기대 결과는 잘못된 상태다. 원인을 찾고 필요한 줄만 고친 뒤 `완료`, `진행 중`, `멈춤`을 다시 실행해 결과를 알려 줘.
```

```py

[debug_status.py (line 5)]의 조건문 한 줄만 수정했습니다.
```
