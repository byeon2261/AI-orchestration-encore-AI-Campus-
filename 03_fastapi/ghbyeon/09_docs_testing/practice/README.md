# 생성형 AI로 Swagger 문서 자동화하기

`study_task_api.py`의 기존 동작을 유지하면서 Swagger UI와 OpenAPI 문서를 완성한다. 생성형 AI 코딩 도구에 구현과 검토를 요청하고 결과를 직접 확인한다.

제출 파일은 문서화를 완성한 `study_task_api.py` 하나다.

## 현재 동작 확인

`03_fastapi_basics` 디렉터리에서 서버를 실행한다.

```powershell
uv run fastapi dev 09_docs_testing/practice/study_task_api.py
```

다음 주소에서 현재 문서를 확인한다.

| 주소 | 확인할 내용 |
| --- | --- |
| `http://127.0.0.1:8000/docs` | 경로, 요청 스키마와 실행 결과 |
| `http://127.0.0.1:8000/redoc` | 읽기 형태로 표현된 API 계약 |
| `http://127.0.0.1:8000/openapi.json` | FastAPI가 생성한 계약 원본 |

세 엔드포인트를 실행해 문서화 전 상태 코드와 응답 본문을 확인한다.

| 상황 | 상태 코드 |
| --- | --- |
| 목록·상세 조회 성공 | `200` |
| 작업 등록 성공 | `201` |
| 존재하지 않는 작업 조회 | `404` |
| 중복 제목 등록 | `409` |
| 요청 검증 실패 | `422` |

서버를 다시 시작하면 메모리에 등록한 작업은 초기화된다.

## 구현 요구사항

생성형 AI 코딩 도구에 다음 문서 정보를 추가하도록 요청한다.

- FastAPI 애플리케이션의 `title`, `summary`, `description`, `version`
- 학습 작업 엔드포인트를 묶는 태그와 태그 설명
- 요청·응답 모델의 필드 설명과 유효한 요청 예시
- 각 엔드포인트의 `summary`, `description`, `response_description`, `tags`
- 실제 반환값과 일치하는 `response_model`
- `201` 정상 응답과 `ErrorResponse`를 사용하는 `404`, `409` 응답 설명 및 예시

다음 조건도 함께 전달한다.

- `study_task_api.py`만 수정한다.
- 기존 URL, HTTP 메서드, 상태 코드와 검증 조건을 유지한다.
- 함수 내부의 작업 등록·조회 로직을 변경하지 않는다.
- 새로운 엔드포인트나 외부 패키지를 추가하지 않는다.
- 설명과 예시는 한국어로 작성한다.

수정이 끝나면 기존 API 동작, OpenAPI 계약과 실제 응답이 일치하는지 검토하도록 요청한다. 발견한 문제는 근거와 함께 설명하고 필요한 부분만 수정하도록 한다.

## 결과 확인

먼저 변경된 코드와 파일 범위를 확인한다.

```powershell
git diff -- 09_docs_testing/practice/study_task_api.py
```

Swagger UI 또는 Postman에서 다음 요청을 실행한다.

| 요청 | 예상 상태 | 확인할 내용 |
| --- | --- | --- |
| 작업 목록 조회 | `200` | `items`와 `total`이 응답 모델과 일치한다. |
| 새로운 작업 등록 | `201` | 새 ID와 `planned` 상태를 반환한다. |
| 같은 제목 다시 등록 | `409` | 중복 제목 오류 모델을 반환한다. |
| 존재하지 않는 ID 조회 | `404` | 작업 없음 오류 모델을 반환한다. |
| 빈 제목이나 범위 밖 시간 등록 | `422` | Pydantic 검증 오류를 반환한다. |

마지막으로 다음 내용을 확인한다.

- 변경된 파일이 `study_task_api.py` 하나다.
- 기존 경로, 검증 조건과 업무 로직이 유지된다.
- 요청 예시가 모든 검증 조건을 만족한다.
- 정상·오류 응답 문서가 실제 상태 코드 및 응답 본문과 일치한다.
- OpenAPI 문서에 코드에 없는 기능이나 응답이 추가되지 않는다.
