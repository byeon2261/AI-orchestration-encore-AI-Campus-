# FastAPI 기초

Python 함수와 타입 힌트를 HTTP API로 연결하고, 요청 검증부터 비동기 처리·문서화·테스트·CRUD까지 하나의 서비스 흐름으로 확장한다. 각 주제는 독립적으로 실행할 수 있고 마지막 CRUD 예제에서 구조를 통합한다.

## 학습 순서

| 순서 | 주제 | 핵심 결과물 |
|---:|---|---|
| 1 | [FastAPI 설치·HTTP·REST] | 서버를 실행하고 GET·POST 엔드포인트를 만든다. |
| 2 | [경로·쿼리 매개변수] | URL의 값과 검색 조건을 구분해 처리한다. |
| 3 | [Pydantic 요청 검증] | 입력 규칙과 오류 응답을 모델로 정의한다. |
| 4 | [응답 모델·출력 계약] | 외부에 공개할 응답 필드를 제한한다. |
| 5 | [의존성 주입] | 인증과 공통 매개변수를 재사용한다. |
| 6 | [비동기 처리·외부 API] | 대기 작업을 비동기로 처리하고 외부 응답을 연결한다. |
| 7 | [예외·미들웨어·CORS] | 오류와 요청 공통 처리를 일관된 구조로 만든다. |
| 8 | [Swagger 문서·API 테스트] | OpenAPI 문서와 자동 테스트로 API 계약을 검증한다. |
| 9 | [CRUD 통합·AI 코드 리뷰] | 계층을 나눈 CRUD 서비스와 리뷰 근거를 만든다. |

## 커밋 메시지 규칙

커밋 메시지는 `유형: 변경한 내용` 형식으로 쓴다. 한 커밋에는 한 가지 작업을 담고, 변경 내용을 짧고 구체적으로 적는다.

- `add`: 코드나 기능 추가
- `fix`: 오류 수정
- `docs`: README 등 문서 수정

예시:

```text
add: FastAPI 경로 매개변수 예제 작성
fix: 잘못된 요청의 검증 오류 수정
docs: 실행 방법 추가
```
